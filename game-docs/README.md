# game-docs — сайт-библия проекта ZOMBI

Отдельная папка проекта: документация, картинки и превью 3D-моделей. Она **не смешивается** с
архивами в корне репозитория (`ZOMBI.7z.*`, `остров 1.7z.*`, `персонаж 1.7z.*`) и с будущим
Godot-проектом — так ничего не теряется и не мешает сборке игры.

- **Сайт (всегда онлайн):** https://rewg40.github.io/my-godot-game/
- **Редактировать:** «✎ Редактировать вкладку» или форма под открытыми вопросами. «Сохранить во вкладке» работает без токена и хранит правку в этом браузере.
- **Опубликовать для всех:** «⤒ Опубликовать вкладку» после подключения GitHub владельца. Токен не попадает в ссылки или репозиторий.
- **Отправить ИИ:** «Сохранить и отправить ИИ» создаёт задачу в `agent-inbox` на целостную обработку; затем автор пишет агенту «разбери inbox».
- **Показать другому человеку:** «Поделиться» → гостевая ссылка. Клиентский замок не защищает публичные файлы; подробнее — `src/docs/USAGE.md`.
- **Вкладки:** Сценарий · Механика (13 подвкладок, включая «Физика») · Картинки / превью.
- **Агенту:** точка входа — `README.md` в корне репозитория (таблица «что → в какой файл»), карта правок — в `config.json` (`site`, `routes`). Адрес сайта агенту не нужен: правятся JSON, Pages пересобирается сам.
- **Агент:** правит те же файлы (`game-docs/src/content/*.json`) и пушит — сайт обновляется сам
  через GitHub Actions. Заявки агенту: внизу сайта → «Запросы агенту» (файлы в `src/content/agent-inbox/`).

```
game-docs/
├── README.md                 ← этот файл
└── src/                      ← сайт (публикуется на Pages как корень)
    ├── index.html            ← три вкладки
    ├── app.css               ← тёмная тема, таблицы, галерея
    ├── app.js                ← рендер JSON, редактор, GitHub API, загрузка картинок/моделей, вьювер GLB
    ├── config.json           ← доступ (SHA-256 коды), пути, репозиторий/ветка
    ├── content/              ← ВЕСЬ КОНТЕНТ И АССЕТЫ
    │   ├── scenario.json     ← вкладка 1
    │   ├── mechanics.json    ← индекс подвкладок вкладки 2
    │   ├── mech_*.json       ← 13 разделов механики
    │   ├── preview.json      ← вкладка 3 (текстовая часть)
    │   ├── images.json       ← реестр картинок (файлы в images/)
    │   ├── models.json       ← реестр 3D-моделей (файлы в models/)
    │   ├── images/           ← концепты и скриншоты (≤1,5 МБ, WebP)
    │   ├── models/           ← превью GLB/GLTF (≤24 МБ)
    │   └── agent-inbox/      ← заявки агенту (после обработки — в done/)
    └── docs/                 ← USAGE.md (для автора) и AGENT-GUIDE.md (для агента: стандарт
                                 детальной проработки + правила Godot 4.x)
```

## Как это опубликовано

1. Пуш в ветку-источник, указанную в workflow, с изменением в `game-docs/**` → запускается
   `.github/workflows/deploy-docs-site.yml`.
2. Workflow проверяет JSON, собирает `game-docs/src/` → публикует в ветку `gh-pages` (корень сайта).
3. GitHub Pages раздаёт `gh-pages` → сайт доступен по адресу выше, бесплатно и без серверов.

Ручной перезапуск: `gh workflow run "Deploy docs site (ZOMBI bible)" --ref <ветка>`.

Если GitHub Pages ещё не включён, workflow попытается включить сам (шаг
«Ensure GitHub Pages enabled»). Если его не пустили права — включи один раз руками:
Settings → Pages → Source: **Deploy from a branch** → Branch: **gh-pages** / **/(root)** → Save.
Дальше всё публикуется автоматически при каждом коммите в `game-docs/**`.

## Локально

```bash
npm ci --prefix game-docs
npm test --prefix game-docs
cd game-docs/src && python3 -m http.server 8081     # → http://localhost:8081
```
Без токена доступно полноценное локальное редактирование вкладок и вопросов: правки лежат в localStorage браузера и переживают обновление страницы. Общая публикация требует GitHub-токен владельца.
