# Как пользоваться сайтом (для автора)

Сайт-библия игры живёт вечно на GitHub Pages: **https://rewg40.github.io/my-godot-game/**
Данные — в твоём репозитории `rewg40/my-godot-game`, в папке `game-docs/`. Это и есть «подключение» агента: он правит те же файлы, которые читает сайт.

## 1. Вход и запрет чужих

- Открываешь сайт → появляется запрос **кода доступа**. Твой личный код: `ZOMBI-2026` (это код владельца: он может добавлять и отзывать доступ).
- **Замок встроен прямо в `index.html`** (генерируется `node game-docs/tools/build-inline-gate.js`): код проверяется на странице, даже если `app.js`, `config.json` и сеть недоступны. Поэтому «открывает только окно с кодом» больше не может быть вызвано старым/заблокированным скриптом.
- Кнопки на экране замка: **⟳ Перепроверить конфиг** (перезагрузка страницы) и **⤓ Сбросить кэш** (забыть вход и скачать `app.js`/`app.css` заново, минуя кэш).
- Полезные параметры адреса: `?open=1` — просмотр без кода (запись отключена), `?reset=1` — сбросить вход и кэш-флаги, `?nc=1` и `?fresh=1` — принудительно «свежая» страница (перескачать `app.js`/`app.css` мимо кэша).
- Быстрый вход по ссылке: `https://rewg40.github.io/my-godot-game/#code=ZOMBI-2026` — код подставится и проверится сам (ссылку гостю можно слать только вместе с кодом, который для него создан).
- 👁 рядом с полем показывает введённый код — имей в виду, что на экране это читаемо.
- Проверка кода работает **без сети**: хеш сверяется с константой внутри `app.js`. VPN не нужен, `github.com` и `github.io` для входа не опрашиваются.
- Если не пускает, смотри строчку внизу замка: `site <версия> · config: …`
  - `config НЕ загружен` → нет доступа к `github.com` (или Pages ещё не собрал конфиг) — обнови страницу;
  - `Код не подходит. Хеш введённого: xxxx…` → такой строки нет в `config.json` → добавь код в «Настройки → Доступ» и дождись деплоя (~1 мин);
  - хеш считается и без WebCrypto (через HTTP/прокси), так что «нет доступа» из-за браузера больше не бывает.
- `config не загружен (сеть)` — сайт работает из кэша: вход есть, но гостевые коды и запись подождают сети. Кнопка «⟳ Перепроверить конфиг» дочитает конфиг без перезагрузки.
- **Увидел старый экран без кнопки «⟳ Перепроверить конфиг»** — браузер держит кэш: закрой вкладку, открой заново по ссылке с `#code=` или нажми Ctrl+F5 (на телефоне — «Обновить» в меню / очищать сайт в настройках браузера).
- Кому разрешить: ⚙ Настройки → «Доступ» → «Сгенерировать» → отправить получившийся код человеку → «Отправить config.json в репозиторий». Коды хранятся как SHA-256, в коде сайта их не видно.
- Отозвать доступ: удалить строку хеша из списка и закоммитить config.json снова.
- Если токен не задан, можно читать; писать — только если в ⚙ задан твой GitHub-токен с правом `repo`/Contents: Write.

### Если вкладка не отреагировала на нажатие

Сайт устроен так, чтобы молчаливых поломок не было. Кнопки вкладок вешаются в самую первую
секунду загрузки — до запроса конфига и до любых сетевых проверок, поэтому нажатие не может
«потеряться» из-за того, что что-то не докачалось. Плюс в сам `index.html` вшит независимый
сторож (`game-docs/tools/inline-watchdog.js`):

- он считает клики по вкладкам и подвкладкам (`window.__ZOMBI_CLICKS__`, `__ZOMBI_LASTTAB__`);
- при любой ошибке скрипта или обещании, которое не исполнилось, показывает внизу слева
  красную карточку «Сторож сайта: вот что не так» с текстом причины;
- если через 7 секунд документ так и не загрузился — говорит об этом прямо;
- в карточке есть кнопки **«Перезагрузить начисто»** (сбрасывает кэш-флаги и открывает
  `?fresh=1`), **«Скопировать»** (полная диагностика: версия `app.js`, версия HTML, клики,
  текст ошибки — это можно сразу отправить агенту) и **«Скрыть»**.

В подвале страницы есть ссылка **«Проверить, слушает ли браузер клики»**. Нажми её: если текст
под кнопками изменился — браузер выполняет код страницы, и там же написано, жив ли `app.js`
(`app.js: жив, версия …` или `app.js: НЕ загрузился или заблокирован`). Это самый быстрый способ
понять, виноват кэш, блокировщик или сами файлы на GitHub.

Если в карточке написано «app.js: НЕ загрузился или заблокирован», значит до тебя не доехал
**файл интерфейса**, а не текст: github.io у нас в стране режут, а `index.html` при этом живёт в
кэше браузера. Сайт это умеет обходить сам — он пробует `cdn.jsdelivr.net`, `rawcdn.githack.com` и
другие адреса; тот, который сработал, дописан в строчке внизу замка («сайт работает с зеркала: …»).
Если ни один автоматический адрес не подошёл:

- **«Офлайн-копия»** в красной карточке — выкачает всю библию (все разделы текстом) в файл
  `zombi-bible.txt`, и его можно читать без интернета;
- `?mirror=https://адрес-зеркала/` — сайт начнёт брать файлы оттуда (адрес запоминается;
  сброс — `?mirror=0`);
- можно открыть сам `https://cdn.jsdelivr.net/gh/rewg40/my-godot-game@gh-pages/index.html` —
  это копия того же сайта, только написанная «на прямо» (запись через неё не работает, чтение — да).

Что делать по шагам, если карточки нет, а вкладки мёртвые:

1. Добавь к адресу `?fresh=1` — страница перескачает файлы минуя кэш:
   `https://rewg40.github.io/my-godot-game/?fresh=1`
2. Не помогло — добавь `#code=ZOMBI-2026`, чтобы войти, не трогая сохранённый токен.
3. Посмотри штамп внизу страницы: `site 2026-11-01.2 · …`. Если агент знает, что выложил
   версию новее — значит до тебя доехал кэш, и «Перезагрузить начисто» это лечит.
4. Скинь агенту текст красной карточки (кнопка «Скопировать») или скажи, какой штамп в подвале.


## 3. Как править текст

1. Наведи курсор на любой блок → справа появятся кнопки `✎ ✕ ↑ ↓ ＋`.
2. `✎` — редактировать. Формат простой, как в Markdown:
   - пустая строка — новый абзац;
   - `- ` список, `1. ` нумерованный, `- [ ]` чек-лист;
   - таблица: первая строка — заголовки через `|`, вторая — `---`;
   - ` ``` ` — код, `> ` — врезка, `## ` — заголовок подраздела;
   - `![подпись](images/preview/file.webp)` — картинка.
3. Правки сразу сохраняются в браузере (жёлтая плашка «есть несохранённые правки»).
4. `⤒ Сохранить в GitHub` (или `Ctrl+S`) — коммит в репозиторий. Через ~1 минуту изменения видны всем, у кого есть код.
5. Если правка не нужна: «Отменить правки» — вернётся версия из репозитория.

## 4. Картинки и 3D-модели

- **Картинка:** вкладка «Картинки / превью» → «＋ Картинка» → перетащить файл. Сайт сожмёт (≤ 1400 px, WebP), зальёт в `game-docs/src/content/images/…` и добавит в реестр.
- Нет токена? Тогда «вместо файла — ссылка»: дай URL `https://raw.githubusercontent.com/rewg40/my-godot-game/<ветка>/game-docs/src/content/images/...`, а файл пусть положит агент.
- **3D-модель:** «＋ 3D-модель» → GLB/GLTF/FBX/OBJ (до 24 МБ) → попадёт в `game-docs/src/content/models/` + запись в `models.json`. Кнопка «👁 превью» крутит модель на сайте.

## 5. Как работать с агентом

### Нужно ли писать агенту адрес сайта?

**Нет.** Сайт статичен и читает JSON из репозитория: «заполнить сайт» = поправить
`game-docs/src/content/*.json` и запушить — Actions сами пересоберут Pages за 10–60 с.
Поэтому адрес сайта агенту не нужен, нужен только путь к папке с контентом.

Исключение — если ты отправляешь задачу **другому** агенту (Claude, Copilot, Cursor):
тогда достаточно одной строки, всё остальное он прочитает в репозитории:

> работай по `README.md` в корне репозитория `rewg40/my-godot-game`, заполни: <что нужно>

Карта «что → куда» лежит там же и в `config.json` (ключ `routes`), полная инструкция —
`game-docs/src/docs/AGENT-GUIDE.md`. Мне здесь, в чате Arena, адрес писать не нужно: файлы,
ветка и деплой мне известны — формулируй содержание.


- Пишешь агенту сюда, в чат Arena: «добавь в Погоду 4 сезона и таблицу эффектов» — он откроет `game-docs/src/content/mech_weather.json`, допишет блоки, закоммитит, запушит; сайт обновится сам.
- Или через сайт: «Запросы агенту» (внизу) → текст → «Отправить агенту» → появится файл в `game-docs/src/content/agent-inbox/`. Дальше скажи агенту: «разбери inbox».
- Полная инструкция для агента (формат JSON, стандарт детализации, правила Godot): ссылка «Инструкция для агента» внизу сайта и файл `game-docs/src/docs/AGENT-GUIDE.md`.

## 6. Где что лежит в репозитории

```
game-docs/                 ← «папка проекта документации», отдельно от архивов и Godot-проекта
├── src/                   ← сайт (index.html, app.css, app.js, config.json)
│   ├── content/           ← ВЕСЬ КОНТЕНТ: scenario.json, mech_*.json, preview.json, images.json, models.json
│   │   ├── images/        ← картинки для галереи
│   │   ├── models/        ← 3D-модели (превью)
│   │   └── agent-inbox/   ← твои запросы агенту
│   └── docs/              ← эта инструкция + AGENT-GUIDE.md
└── README.md
.github/workflows/deploy-docs-site.yml   ← автопубликация на Pages
```

Архивы `ZOMBI.7z.*`, `остров 1.7z.*`, `персонаж 1.7z.*` в корне не трогаем: они нужны как исходники. Когда будешь готов — агент предложит перейти на Git LFS, чтобы репозиторий не раздувался.

## 7. Частые вопросы

- **Сайт не обновился после сохранения.** Коммит есть, а Pages нет? Подожди минуту; «↻ Обновить» подтянет из репозитория. Проверить сборку: `gh run list --workflow "Deploy docs site (ZOMBI bible)"`.
- **Пишет 404/403 при сохранении.** Нет токена, токен без прав на запись, или указана чужая ветка. ⚙ → «GitHub».
- **Хочу, чтобы контент писался в main, а не в рабочую ветку.** Поменяй ветку в ⚙ (например `main`) — тогда сайт будет читать/писать там, а агент продолжит на своей ветке; чтобы не разъезжалось, держи одну ветку-источник.
- **Картинка не показывается.** Значит файл ещё не долетел на Pages или путь в `images.json` не совпадает с реальным. Путь всегда относительно `content/`.
- **«Нажимаю вкладку — ничего не происходит.»** Смотри §2 «Если вкладка не отреагировала на нажатие»: обычно это кэш браузера (лечится `?fresh=1` или кнопкой «Перезагрузить начисто» в красной карточке сторожа), а если файлы действительно не те — карточка сторожа покажет причину текстом.
- **Открыть локально:** `cd game-docs/src && python3 -m http.server 8081` → http://localhost:8081 (без сервера и токена сайт работает в режиме «только чтение + черновики»).
