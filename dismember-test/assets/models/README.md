# Ассеты полигона

Модели лежат в репозитории ассетов
[`rewg40/pepel-i-zvezdy`](https://github.com/rewg40/pepel-i-zvezdy) — папками
и разрезанными архивами. Скачать и разложить их можно одной командой:

```bash
python tools/fetch_models.py
```

Скрипт скачивает тома `.z01/.z02/.zip`, склеивает их (у этих архивов
смещение каталога считается от последнего тома, поэтому обычный `unzip`
на них ругается), распаковывает и сразу режет зомби и медика на части.
Файлы берутся с `raw.githubusercontent.com`, а если сеть его не пускает —
через `api.github.com` с типом `application/vnd.github.raw`.
Нужен только `numpy` для нарезки:

```bash
python -m pip install numpy
```

| Файл | Откуда в репозитории ассетов | Размер | В git |
|---|---|---|---|
| `sword.glb` | `предмет/Dragon Broadsword with Cyan Hilt.glb` | 6.9 МБ | **да** |
| `island_improved.glb` | `остров/2 остров улучшенный.z01…zip` | 114 МБ | нет |
| `island.glb` | `остров 1.7z.001…002` из корня этого репозитория | 66 МБ | нет |
| `zombie.glb` | `зомби/ZOMBI.z01…z03 + ZOMBI.zip` | 90 МБ | нет |
| `character.glb` | `персонаж/медик.z01, z02 + медик.zip` | 80 МБ | нет |
| `zombie_parts.glb` | делает `fetch_models.py` / `prepare_assets.py` | 133 МБ | нет |
| `character_parts.glb` | то же для медика | 107 МБ | нет |
| `*_parts.json` | шарниры и габариты частей | 2 КБ | нет |

Тяжёлые модели в git не попадают: у GitHub лимит 100 МБ на файл, а держать
300 МБ в истории бессмысленно — они восстанавливаются одной командой.

## Отдельные ключи

```bash
python tools/fetch_models.py --only sword          # только меч
python tools/fetch_models.py --only island         # только улучшенный остров
python tools/fetch_models.py --skip-split          # скачать без нарезки
python tools/fetch_models.py --from-dir /tmp/parts # без сети, файлы уже скачаны
```

Если интернета нет вообще, положите в эту папку готовые `zombie.glb`,
`character.glb`, `island.glb` и запустите:

```bash
python tools/prepare_assets.py --skip-unpack
```

## Что за модели

| Модель | Что внутри |
|---|---|
| Улучшенный остров | 60 мешей, 888 тыс. вершин, 1.49 млн треугольников, рельеф высотой 2.3 км в исходном масштабе (в игре — 25 м). Скульптура, не скелет |
| Зомби | одна скульптура, 865 тыс. вершин, 1.5 млн треугольников, рост 1.03 |
| Медик (из репозитория ассетов) | одна скульптура, 1.48 млн треугольников, рост 1.115, руки опущены (A-поза) |
| Меч | 36 тыс. вершин, 3 текстуры, длина 601 ед. вдоль оси Z: клинок в −Z, рукоять в +Z |

Ни у одной модели нет скелета, весов и клипов анимации — поэтому движения
в игре процедурные, а конечности отделяются вырезанием геометрии.

## Подгонка реза

Правила лежат в `tools/split_profiles.json`. Ключи:

| Ключ | Смысл |
|---|---|
| `hip_y` | доля роста, ниже которой начинаются ноги |
| `shoulder_y` | доля роста, на которой плечи |
| `arm_x` | насколько плечо отстоит от центра по X |
| `arm_radius` | радиус «трубы» вокруг оси руки |
| `arm_taper` | во сколько раз труба расширяется к кисти |
| `center_x` | смещение центра корпуса (у сгорбленного зомби оно не нулевое) |
| `yaw` | доворот модели, чтобы она смотрела вперёд по −Z |
| `t_pose_drop` | на сколько градусов опускать руки, если модель стоит в T-позе |

Поза определяется автоматически: если руки вытянуты в стороны (T-поза, как
у `персонаж 1.glb` из корня репозитория), генератор пишет в JSON
`arm_rest_z = 78` — риг довернёт плечи вниз. У медика из репозитория ассетов
руки уже опущены, там `arm_rest_z = 0` и позу никто не трогает.

После правки — снова генератор. В игре нажмите F3: зоны попадания
подсвечиваются красным, сразу видно, куда попал рез.

## Почему рез считается заранее

Скульптуры на 1.5 млн треугольников. Резать их в GDScript на старте значило бы
несколько секунд ожидания на каждый запуск, поэтому разметка считается один раз
в Python (numpy), а движок получает готовый GLB с пятью поверхностями
и JSON с шарнирами.
