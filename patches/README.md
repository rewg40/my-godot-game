# Перенос работы в ветку `arena/73c7370f-my-godot-game` (PR #4)

## Зачем это

Две ветки ведут одну библию параллельно, и содержимое разошлось:

| | эта ветка (`arena/087e4771`, PR #5) | `arena/73c7370f` (PR #4) |
|---|---|---|
| `mech_zombies.json` | 38 блоков: двери, привада, стадии | 20 блоков, старые вопросы |
| `mech_craft.json` | 26 блоков: уровень технологий (УТ) | 21 блок, УТ нет |
| `mech_character.json` | 49 блоков: 4 происхождения, практика, специализации | 28 блоков: «Пирамида прогресса», ветки и ранги |
| `app.js` | сверка с сервером, окно отличий, обработка 409 | защиты нет |

Обычный `git diff` между ветками не ложится: правки переставляют блоки и меняют модели.
Поэтому работа упакована в **смысловой бандл**: операции «вставить раздел перед таким-то
заголовком», «добавить строку в таблицу», «обновить список вопросов» — а не строки diff.

## Состав

| Файл | Что это |
|---|---|
| `content-bundle.json` | сами правки: разделы, строки таблиц, замены формулировок, операции со списками вопросов |
| `apply_bundle.py` | применитель. Идемпотентен (повторный запуск ничего не меняет), пропускает то, чего в целевой ветке нет, и печатает отчёт |
| `appjs-409-guard.patch` | diff правки `app.js` (свежий `sha`, повтор, окно отличий при 409) |
| `appjs-409-guard.snippet.md` | тот же код кусками — если diff не ложится |
| `full-files/` | целые вкладки, которые нельзя слить построчно (см. ниже) |

## Как применять

В ветке `arena/73c7370f-my-godot-game` (из корня репозитория):

```bash
# 1. сначала посмотреть отчёт, ничего не записывая
python3 patches/apply_bundle.py --dry-run --root game-docs/src/content

# 2. применить
python3 patches/apply_bundle.py --root game-docs/src/content

# 3. проверить
for f in game-docs/src/content/*.json; do
  python3 -c "import json,sys; json.load(open(sys.argv[1],encoding='utf-8'))" "$f" || echo "BAD $f"
done
npm test --prefix game-docs
```

Применитель меняет `updated` только в тех файлах, которые реально изменил.
Код выхода: `0` — всё применено, `1` — есть пропуски (см. отчёт), `2` — ошибка.

## Что переносится автоматически

- **ИИ монстров:** разделы «Преграды: не открывают, а выбивают», «Запах как управление:
  привада и отвод», «Стадии → типы»; строка «Бегун» в таблице типов; канал «обоняние»;
  правило про разрушение проёмов; три новых вопроса вместо трёх решённых.
- **Крафт:** раздел «Уровень технологий (УТ)» (таблица УТ0–УТ3 на 140 рецептов, правила,
  `TechLevel` + `can_craft`), раздел «Запах как инструмент» (4 рецепта: привада, «отвод»,
  баррикада), колонка «УТ» в таблице стартовых рецептов, принцип «два ключа».
- **Исследование:** стык УТ и tech-пула; источники «Живой образец» и «Феромонный синтез».
- **Квесты:** `q2_shadow` (Тень по имени) и `q2_lure` (отвод стаи).
- **Бой:** привада и «отвод» в таблице отвлечения; пометка, что «Обрез» — награда акта I.
- **Инвентарь:** пахучие расходники (вес, слоты, срок).
- **Локации:** баррикада и время двери.
- **Сетевая игра:** узловые как событие сервера, УТ один на сервер, привада как объект.
- **Ассеты:** порог LFS 1 ГБ, отказ от второго морфа лица, три новых вопроса.
- **Правило «ответ = изменение в проекте»:** решённые вопросы удаляются, вместо них
  добавляются новые.

## Что не переносится автоматически (нужно решение)

1. **`mech_character.json` — другая модель.** Здесь «происхождение + практика + специализация»,
   там «пирамида прогресса, ветки и ранги». Бандл честно пишет:
   `ПРОПУСК вопросов: в целевой вкладке нет понятий «Специализация», «происхождени»`.
   Варианты: (а) заменить файл целиком — `patches/full-files/mech_character.json`;
   (б) оставить старую модель и перенести только вершинный приём с босса вручную.
2. **Тесты.** Новые проверки (`game-docs/tools/test-content.cjs`) завязаны на формулировки
   этой ветки; переносить их нужно вместе с содержимым и перечитывать ожидания.
3. **`AGENT-GUIDE.md`.** Правило «ответ автора = изменение в проекте» (раздел А.2.1) стоит
   перенести текстом: оно про процесс, а не про контент.
4. **`app.js`.** Патч может не лечь: в той ветке сборка сильно новее (галерея, видео-блоки).
   Тогда правки вносятся по `appjs-409-guard.snippet.md`.

**Найденная и исправленная ошибка применителя:** операция замены текста подменяла список

очередь вопросы — применялись к старому списку и не попадали в файл, хотя отчёт показывал
«удалено/добавлено». Ссылка на блоки теперь обновляется после подмены; прогон сверен
по содержимому файлов, а не только по отчёту.
